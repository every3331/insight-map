# 洞见 · Agent 设计说明

> 一句话：**模型只负责"讲"，程序负责"算"和"管"。**

## 1. 为什么只做「一个角色 + 一个接口」

参考过的两部国一作品给了两条反面教训：

| 作品 | 做法 | 问题 |
|---|---|---|
| AI 助手（智析创案） | 前端直连 OpenAI，Key 存在 localStorage | 断网/没 key 就空白；Key 暴露 |
| 文画平台（czb） | 前端硬编码火山/DeepSeek Key，直连 | 同上，且没有输出校验，模型说什么就显示什么 |

所以这里反过来：**所有模型调用都在后端，前端只认结构化结果**。

一个角色：**诊断助教**。职责边界写死在三处：

1. 只能从候选知识点里选 `nodeId`（候选由本地关键词引擎先召回 10 个）；
2. `errorType` 只能取 8 个枚举值；
3. 输出必须是 schema 约束的 JSON —— 模型跑偏就直接判失败，前端回落本地引擎。

## 2. 一次请求的完整链路

```
学生贴题（题干 + 我的写法）
   │
   ├─ 本地召回：recallCandidates(text, 10) → 10 个候选（含 code / level / 前置）
   │
   ├─ POST /api/agent {question, work, candidates}
   │      │
   │      ├─ 有 key → 模型生成 {nodeId, errorType, confidence, diagnosis, steps[], trap, next[]}
   │      │        └─ 服务端校验：nodeId ∉ 候选 → 判失败
   │      ├─ 无 key → 返回「结构合法、内容弱一档」的占位诊断
   │      └─ 模型挂了 → fallback
   │
   ├─ 前端渲染：知识点 / 错因 / 置信度 / 分步讲解 / 最容易错 / 下一步
   └─ 四个动作按钮（闭环）
```

## 3. 闭环在哪（这是"创新性"的落点）

Agent 的结果不是终点，而是一条链的起点。四个按钮全部接到已有模块：

| 按钮 | 接到哪 | 产生的数据 |
|---|---|---|
| 去地图看断点 | 知识地图（`DJ.openNode`） | 节点裂开 + 侧栏展开 |
| 记进错题本 | 错题本（`DJ.addWrong`） | 一条「待修复」+ 一次失败证据 |
| 做同类题 | 刷题页（待修复优先队列） | 新一轮答题 |
| 按断点组卷 | 试卷页（`pickPending`） | 自动勾选相关真题 → 组卷打印 |

于是形成：**诊断 → 定位 → 补课 → 练习 → 再诊断**，每一环都留下数据（证据 n/m），够 2 次正确才算愈合。

## 4. 三级降级（现场不赌网络）

```
Next.js 后端（3100）      ← 正式实现，Vercel AI SDK
     ↓ 没装/没起
零依赖后端 /api/agent     ← node server.js 就能跑，同契约
     ↓ 没配 key
本地规则引擎              ← 完全离线，界面照常
```

前端 `agent.js` 会自动探测三个端点（手动保存 → 同源 → 3100），谁活着用谁；全挂了就走本地引擎并在面板上标「本地引擎」。

## 5. 扩展第二个角色要改哪里

- `web/app/api/agent/route.ts`：按 `body.role` 分派 prompt 与 schema；
- 前端 `agent.js`：面板顶部加角色切换；
- 不需要动知识图谱、错题本、试卷 —— 它们通过 `window.DJ` 与 Agent 解耦。

建议的第二个角色：**出题助教**（按断点参数化出题 + 程序校验答案），仍然遵守"模型不算数学"。
