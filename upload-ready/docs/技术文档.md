## 一、项目概述

### 1.1 背景

学生刷题之后通常只知道"我错了"，却不知道**错在哪一层**：是这一步算错（符号、运算），还是这个概念根本没建立（概念混淆），又或者它的前置知识（比如"导数应用"之前的"导数定义"）本身就虚着。更麻烦的是**补课顺序**——先补哪一节、后补哪一节，顺序错了会越补越乱。

### 1.2 我们的答案

洞见把"一道错题"变成一张**跨学段知识图谱上的断点**，再用「前置关系 + 掌握度 + 证据数」算出一条从地基到断点的**最短补课链**，最后由三个 AI 助教角色把它讲清楚、练扎实：

```
错题 → 诊断（断在哪一层）→ 定位（图谱上哪个节点）→ 规划（先补哪几节）
     → 练习（同类变式 + 试卷）→ 阅卷（得分点自评）→ 证据（2/2 才算掌握）→ 再诊断
```

### 1.3 成果概览

| 维度 | 数字 |
|---|---|
| 知识图谱 | 76 节点（高中 32 / 大学 44）· 78 条前置关系 · 40 章节 · 5 条跨学段连接 |
| 试卷 | 8 套（2018–2025）· 168 题（单选 80 / 填空 24 / 判断 12 / 多选 12 / 大题 40） |
| 题库总量 | 236 题（试卷 168 + 刷题 36 + 变式 12 + 探针 17 + 示例 3） |
| 大题解析 | 30 道双解法 + 每条 1 个常见错解与错因 |
| 视频资源 | 67/76 节点、124 条已核实 B 站视频 |
| AI 角色 | 3 个（诊断 / 规划 / 阅卷），1 个后端接口 |
| 测试 | 20 项单元测试 + 41 项交互巡检 + 8 项静态托管断言 |

## 二、需求分析

### 2.1 用户与场景

| 角色 | 场景 | 关键诉求 |
|---|---|---|
| 高中生 | 高一/高二同步练习，准备衔接大学 | 知道"这一步为什么错"，不被超纲内容劝退 |
| 专升本考生 | 备考高等数学，题型固定 | 真题式训练、大题要能自查、错题要能重做 |
| 自学者 | 无老师答疑 | 随时能问、问完能落到"下一步做什么" |

### 2.2 功能需求

1. 输入一道题（题干 + 自己的写法），得到：错在哪一层 / 关联哪个知识点 / 怎么一步步做对；
2. 在知识地图上看到当前状态，并能从断点往回追前置；
3. 有足够的练习量，且题目要分级（变式 / 探针 / 试卷）；
4. 做过的错题要沉淀、要能重做、要能组卷打印；
5. 学习路径要自动排出先后顺序，而不是给一堆待办；
6. 大题不能靠"我觉得我行"自评。

### 2.3 非功能需求

| 约束 | 我们的选择 |
|---|---|
| 评委/用户环境不确定 | **零依赖**：双击 HTML 就能跑，不需要 npm install |
| 现场可能断网 | **三级降级**：真模型 → 本地引擎 → 纯静态 |
| API 费用自理 | 无 Key 也能完整演示；同一题面可加缓存复用 |
| 用户数据合规 | 全部留在 localStorage，无账号、无上传、无埋点 |
| 后端不作重点考察 | 后端只做 AI 接入层，**一个接口** |

## 三、系统架构设计

### 3.1 总体架构

```
┌──────────────── 前端（零依赖静态应用，考察重点） ────────────────┐
│ index.html                                                      │
│   ├─ app.js       视图路由 / 诊断流程 / 刷题 / 地图 / 错题本      │
│   ├─ graph.js     76 节点 · 78 边 · 40 章（唯一数据真源，DAG）    │
│   ├─ data.js      变式 / 探针 / 题库 / 召回 v2 / 本地诊断         │
│   ├─ papers*.js   8 套卷 168 题（UMD：浏览器与 Node 共用）        │
│   ├─ paper.js     试卷 / 跨卷组卷 / 评分点自评 / A4 打印          │
│   ├─ planner.js   补课路线算法（纯函数）                          │
│   ├─ agent.js     三角色助教面板（上下文感知 + 降级）             │
│   ├─ plot.js      自研函数绘图引擎                                │
│   └─ styles.css   极光青设计系统（23 个 CSS 变量）                │
└──────────────────────────┬──────────────────────────────────────┘
                           │ 可选：POST /api/agent（唯一后端接口）
┌──────────────────────────▼──────────────────────────────────────┐
│ A. 零依赖后端  server.js + server/agent.js（node 直接跑）         │
│ B. 全栈后端    web/app/api/agent/route.ts（Next.js 15 + AI SDK）  │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 数据模型

**知识节点**（`graph.js`，单一真源）：

```js
{ id:'taylor', label:'泰勒公式', level:'uni', book:'高数上', chapter:'3.3',
  code:'3.3', prereq:'der-calc', kw:['泰勒','展开','麦克劳林'], fn:'…', fnx:…, m:0 }
```

- 边由 `prereq` 推导，跨学段边自动标记；
- 图论不变量：**无环 + 全可达**（单元测试逐条校验）。

**学习状态**（localStorage）：

```js
S = { mastery:{nodeId:0..100}, ev:{nodeId:{ok,n,at}}, history:[{nodeId,errorType,state}], … }
```

**试卷**（`papers*.js`）：

```js
{ id:'gd-2024-demo', year:2024, minutes:120, total:100,
  choice:[{no,stem,options,answer,score,nodeId,baby}], objective:[{type:'fill'|'judge'|'multi'}],
  big:[{no,stem,answer,steps,score,nodeId,baby}] }
```

### 3.3 关键流程：一次诊断

```
学生贴题
  │
  ├─ ① 本地召回 v2：素材信号 ×0.5 + 题型信号 + 题型排斥 damp → 10 个候选
  │
  ├─ ② POST /api/agent {question, work, candidates}
  │      ├─ 有 Key → 模型输出 schema 约束的 JSON
  │      ├─ 服务端校验：nodeId ∉ 候选 → 判失败
  │      └─ 无 Key / 失败 → 本地引擎（含候选边界修正）
  │
  ├─ ③ 渲染：知识点 / 错因 / 置信度 / 分步讲解 / 最容易错 / 下一步
  │
  └─ ④ 四个动作（闭环）：去地图看断点 / 记进错题本 / 做同类题 / 按断点组卷
```

### 3.4 技术选型理由

| 选择 | 理由 |
|---|---|
| 原生 HTML/CSS/JS，零构建 | 评审环境不可控：双击即用，无 Node 也能跑；首屏无打包开销 |
| UMD 双端共用数据 | 同一份 `papers*.js` 给浏览器与 Node 单测用，避免数据两处维护 |
| 自研 `plot.js` | 只需画函数曲线 + 割线 + 求导演示；引 Chart.js/D3 反而增加体积与不确定性 |
| Next.js + Vercel AI SDK（可选后端） | 赛项鼓励"现代前端全栈能力"，API Route 天然是"唯一接入层" |
| 结构化输出（zod schema） | 让模型的输出可直接渲染，不需要解析自由文本；越界即判失败 |

## 四、AI 技术方案

### 4.1 选型理由

**问题**：错题诊断是"理解学生写法 + 定位知识点 + 给出可执行步骤"的任务，纯规则做不好（自然语言表述太发散），纯模型又不可控（会编知识点、会算错）。

**结论**：**规则负责"约束"，模型负责"表达"**。

| 决策 | 备选 | 为什么选它 |
|---|---|---|
| 两段式（先召回再让模型选） | 让模型直接输出知识点 | 模型自由发挥会编出不存在的节点；限定在 10 个候选内，越界即失败 |
| JSON schema 结构化输出 | 自由文本 + 前端解析 | 结构化可直接渲染；解析自由文本会因格式漂移而崩 |
| OpenAI 兼容网关 + `AGENT_MODEL` 可换 | 绑定单一厂商 | 换模型只改环境变量；评测期可切便宜模型 |
| 本地引擎兜底 | 只用模型 | 断网/无 Key/额度耗尽时功能不能断 |
| **不做端侧大模型**（本轮） | Transformers.js 跑 LLM | 120MB 权重 + 首屏等待，与"零依赖双击即用"冲突；端侧语义召回见展望 |

### 4.2 集成方式

**一个接口，三种模式**：

| 模式 | 用途 | 输出 |
|---|---|---|
| `diagnose` | 诊断 | 结构化 JSON（nodeId 必在候选内） |
| `stream` | 边讲边看 | 文本流（26 字/块） |
| `chat` | 多轮追问 | 文本流（携带最近 8 轮） |

关键代码（`web/app/api/agent/route.ts`）：

```ts
const DiagnoseSchema = z.object({
  nodeId: z.string(), errorType: z.string(), confidence: z.number(),
  diagnosis: z.string(), verdict: z.enum(['wrong','right','unclear']).optional(),
  steps: z.array(z.string()).min(2).max(6).optional(),
  trap: z.string().optional(), next: z.array(z.string()).max(3).optional(),
});

const { object } = await generateObject({ model: model(), schema: DiagnoseSchema, prompt });
if (cands.length && !cands.some(c => c.id === object.nodeId)) {
  return json({ ok:false, error:'nodeId 不在候选集' });   // 越界即失败 → 前端回落
}
```

**Key 安全**：只在服务端（环境变量或 `.agent-config.json`）；设置接口仅接受 127.0.0.1；
`GET /api/agent` 只回掩码（如 `sk-t…cdef`），任何接口都不回明文。

### 4.3 优化策略

| 优化 | 做法 | 效果 |
|---|---|---|
| **候选约束** | 召回 10 个候选，模型只能选其一 | 消除"知识点幻觉"，前端可直接定位 |
| **schema 硬校验** | 字段类型/枚举/长度全部约束 | 输出可直接渲染，不再需要"兜底解析" |
| **三级降级** | 模型 → 本地引擎 → 纯静态 | 任何环境都能演示 |
| **提示词分工** | 系统提示只讲"角色 + 规则"，不塞题库 | 降低 token，减少跑题 |
| **上下文感知** | 前端把"当前页面/当前题/当前节点"作为上下文传入 | 用户不用重复描述，追问更准 |
| **温度控制** | 诊断 0.2（稳定）、详解 0.3–0.4（自然） | 结构化任务更稳，讲解更顺 |
| **防止自评放水** | 大题改为"按得分点勾选"，分数由程序算 | 证据可信度提升（详见 5.6） |
| **路径不走模型** | 补课顺序由拓扑排序算出 | 可验证、可单测、零成本 |

### 4.4 评测

- **召回评测集**：30 条人工标注（题干 → 期望节点），v1 关键词命中 21/30，v2（素材信号 + 题型信号 + 排斥）命中 **30/30**；
- **越界率**：候选约束下，"模型输出不在候选集"的比例由前端日志统计，当前演示集为 0；
- **降级验证**：断网、清空 Key、只开机静态三种情形下，诊断均能返回结果（来源分别标注为 模型 / 本地引擎）。

## 五、核心功能实现

### 5.1 两段式诊断（`data.js` + `app.js`）

1. **召回**：`recallCandidates(text, 10)` — 关键词命中（含同义词）、题型信号（如出现"lim"加权极限类）、素材信号（题目里出现函数式则偏向该函数所属章节）、题型排斥（判断题不偏向计算题节点）；
2. **约束**：候选集合连同 `code/label/level/prereq` 一起发给模型；
3. **校验**：`validDiag()` 检查 nodeId 存在、errorType 在枚举内、confidence ∈ [0,1]、diagnosis 长度 4–200；
4. **降级**：任何一步失败 → `diagnoseLocal()`。

### 5.2 证据模型（"2/2 才算掌握"）

```js
S.ev[nodeId] = { ok, n, at }      // ok: 正确次数, n: 总证据数
healNode(nodeId) 需要 ok >= 2      // 单次答对不愈合
```

- 客观题：答对 → `addEvidence(id, true)`；答错 → `addWrong(id, 错因)`；
- 大题：自评 ≥60% → 记一次正确证据；<40% → 进错题本；40–59% 为灰区（不计证据，防放水）。

### 5.3 知识地图

- **星图**：9 条教材泳道，节点半径映射掌握度，语义缩放（`k<0.85` 隐藏标签）；
- **焦点图**：选中节点后只画它 + 前置 + 后继，避免 76 节点全图糊成一团；
- **四态**：已掌握 / 待巩固 / 薄弱 / 断点，颜色 + 裂纹路径区分。

### 5.4 试卷与组卷

- 五类题型统一 `renderTyped()` 渲染，客观题统一判分入口；
- **跨卷自由加题**：任意卷任意题打勾 → 「组卷」→ A4 打印（`@page size:A4`，答案另页 `page-break-before`）；
- **按断点抽题**：`pickPending()` 从错题本反查 nodeId → 自动勾选同知识点题目。

### 5.5 规划助教（纯算法）

```
断点集 B
  for b in B: 沿 prereq 走到根，保留 { 掌握度<70 或 本身是断点 } → need
  sort need by (深度 asc, 被依赖数 desc)  → 取前 6 步
  每步给一句"为什么先做它"（被 N 个断点依赖 / 是地基 / 你确实断过）
```

- 复杂度 O(|B| × 链长)，无网络、无模型调用；
- 输出卡片带三个入口：地图定位 / 看这个课 / 让助教讲。

### 5.6 阅卷助教（得分点自评）

把标准解法的每一步当作一个**得分点**（`分值 ÷ 步数`），学生逐条勾选，分数由程序算：

```
每步 2.5 分 → 勾 2 步 = 5 分 → ≥60% 记正确证据，<40% 进错题本
```

相比"拖一个总分滑块"，自评有了**可对照的依据**，也让证据链可信。

### 5.7 自研绘图引擎（`plot.js`）

- 支持一次/二次/三次/三角/指数/对数/分式函数与参数曲线；
- 逐笔绘制动画（`pathLength` 1 → 0）、割线 → 切线动画（`err-arc` 错→对位移弧线）；
- 输入 `(x, y)` 输出 `f′≈d` 的实时数值面板，把"导数=斜率"变成可操作的东西。

## 七、总结与展望

### 7.1 已完成

- 把"错题"从一次性反馈变成**可执行、可验证、可追踪**的补课链；
- 用图谱 + 证据 + 拓扑排序三个**确定性组件**，把 AI 的发挥空间限制在"表达"上；
- 在无后端、无网络、无 Key 三种极端条件下都能完整演示。

### 7.2 不足

1. 试卷为按考纲重构的示例卷，尚未替换为官方真题；
2. 大题双解法覆盖 30/40，2018/2025 两套仍为单解法；
3. 端侧推理尚未落地；
4. 教师端（班级断点热力图）未做。

### 7.3 展望

1. **端侧语义召回**：Transformers.js 加载多语种小模型，把题干编码成向量，替代关键词召回；WebGPU 不可用回退 WASM，再回退现算法（与现有三级降级同构）；
2. **真题替换 + 题库扩容**：按现有 schema 直接替换数据文件，界面零改动；
3. **班级视图**：以断点分布生成讲评课案（3 道典型题 + 讲解顺序）；
4. **证据时效**：引入遗忘曲线（SM-2），掌握度随时间衰减，错题本按"今天该复习"排序。

## 八、创新点说明

### 8.1 技术创新

| # | 创新点 | 与常见做法的差别 |
|---|---|---|
| 1 | **受约束的两段式诊断** | 常见做法是"模型直接说这是哪个知识点"；我们先用本地算法召回 10 个候选，模型只能在其中选，越界即判失败 |
| 2 | **证据模型（2/2 才算掌握）** | 常见做法是"答对一次就算会"；我们要求两次以上正确证据才愈合，且大题按得分点核算 |
| 3 | **规划走算法，不走模型** | 常见做法是让模型"给个学习计划"；我们用拓扑排序算出先修链，可单测、可验证、零成本，模型只负责措辞 |
| 4 | **三级降级架构** | 常见做法是"没 Key 就空白"；我们做到 模型 → 本地引擎 → 纯静态 三级可用，且界面明示来源 |
| 5 | **零依赖 + UMD 双端数据** | 同一份题库/图谱既给浏览器又给 Node 单测使用，双击即可运行，评审环境零门槛 |
| 6 | **自研绘图引擎** | 不引第三方图表库，函数曲线、割线→切线动画、求导数值面板全部自绘 |

### 8.2 应用创新

| # | 创新点 | 价值 |
|---|---|---|
| 1 | **跨学段知识图谱**（高中 32 + 大学 44，含 5 条跨层连接） | 专升本/衔接场景真正需要"往上追前置"，单一学段图谱做不到 |
| 2 | **错题 → 断点 → 补课链**的一体化 | 学生拿到的不再是"你错了"，而是"先补 A 再补 B，今天 20 分钟" |
| 3 | **按得分点自评** | 把"我觉得我行"变成"我对照得分点逐条核对"，解决自评放水 |
| 4 | **跨卷自由组卷 + A4 打印** | 老师/学生可以把"我的错题同类题"直接打成一张卷子 |
| 5 | **可断网的完整演示** | 面向真实评审场景设计，网络不可控时功能不降级（只降模型） |
