# 部署到 GitHub Pages（静态版在线演示）

> 目标：给评委一个**点开就能用**的公网地址。纯静态，零费用，零维护，评审期间几乎不会挂。

## 一、先搞清楚这个版本的边界

| 项 | 静态版（Pages） | 本地全功能版（`node server.js`） |
|---|---|---|
| 诊断 / 刷题 / 知识地图 / 试卷 / 错题本 / 规划 / 阅卷评分点 | ✅ 全部可用 | ✅ 全部可用 |
| AI 助教 | ✅ 可用，但走**内置诊断引擎**（离线算法） | ✅ 可用，接真模型 |
| 数据 | 存在浏览器 localStorage | 同左 |

页面加载后会在顶部显示一条横幅说明这件事——**这是设计，不是缺陷**：评委看到的是"我们做了三级降级，没有网络/没有 key 也能用"。

## 二、发布步骤（5 步，约 5 分钟）

前提：仓库已经是 Public。

1. 把代码推上 GitHub（根目录需要有 `index.html` 与 `.nojekyll`，本项目已经准备好）；
2. 打开仓库 → **Settings** → 左侧 **Pages**；
3. **Source** 选 `Deploy from a branch`，**Branch** 选 `main`，目录选 `/ (root)`，点 **Save**；
4. 等 1–2 分钟，页面顶部会出现地址：
   ```
   https://<你的用户名>.github.io/<仓库名>/
   ```
5. 打开验证：
   - 首页是「洞见」落地页（标题 + 数据 + 进入作品按钮）；
   - 点「进入作品 →」跳到 `/<仓库名>/insight-map/`；
   - 顶部出现青色横幅「在线体验版」；
   - 贴一道题 → 点「诊断这道题」→ 能出结果（来源显示"本地引擎"）。

## 三、几个关键文件（别删）

| 文件 | 作用 |
|---|---|
| `index.html`（仓库根） | Pages 的入口，落地页 + 跳转到 `insight-map/` |
| `.nojekyll`（仓库根） | 关掉 Jekyll，否则以下划线开头的文件会被忽略 |
| `insight-map/index.html` | 真正的应用入口 |

## 四、常见问题

**Q：页面 404 / 白屏？**
A：检查 Pages 的 Branch 是否选了 `main` + `/ (root)`；首次部署要等 1–2 分钟；地址末尾要有斜杠。

**Q：AI 助教点了没反应？**
A：静态版没有后端，面板会显示“无后端（本地引擎）”，这是预期行为；诊断仍然可用。想验证真模型，本地跑 `node server.js`。

**Q：想强制它去试后端？**
A：地址加 `?api=1`，例如 `.../insight-map/?api=1`。没有后端时会自动回落。

**Q：国内访问慢？**
A：GitHub Pages 偶尔慢但通常可用。若评审明确反馈打不开，把同一份文件放 Gitee Pages 作为备用地址（代码不用改）。

**Q：数据会不会丢？**
A：数据存在**每个访客自己的浏览器**里，换设备/清缓存就会重置；页面底部已写明“不上传、无账号、无追踪”。
